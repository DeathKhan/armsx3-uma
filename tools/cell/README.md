# Cell phase-one fixtures

`bash tools/cell/test-topology.sh` tests capacity selection, restricted/unknown/three-tier fallback, the exact master switch, and Android calls before driver_env initialization. `bash tools/cell/test-wait.sh` stresses the registered-wait handoff using the production phase object and Linux futexes across 200,000 publication/notification races. Outputs stay in `target/cell-tests/`.

`bash tools/cell/tests/run_wait_engine.sh` compiles the production atomic.cpp directly and tests both master states through the Android registered-wait/futex path: 20,000 notifications, 2,000 multi-address waits, forced wake, six-way wake-all, finite timeout, initial cancellation, callback timeout override, and empty registry. `bash tools/cell/tests/run_wait_engine.sh --android` cross-compiles the same fixture to `target/cell-tests/test-wait-engine-android-arm64` for a device run. Only unrelated diagnostic/sysinfo definitions are stubbed; host TSC is not a performance measurement.

The host wait fixtures do not prove AArch64 SEV/WFE behavior, guest channel semantics, game correctness, or energy savings. Those require the Android phase checkpoint.

The wait integration retains the existing atomic_wait_engine registration, multi-address comparisons, cancellation callbacks, condition lifetime and forced-notification protocol. Only PPU/SPU hosts use a bounded 3 ms WFE phase and only with HWCAP_EVTSTRM. It becomes an ordinary futex after the budget. RSX and helper waits keep their sleeping path. Scoped suppression in thread_ctrl::wait_for/accurate and lv2_obj::wait_timeout keeps timer/usleep pacing and lv2 timeout sleeps on the existing native path, including when called from a PPU/SPU host. Logical waits shorter than 200 us also remain native. Nested suppression restores the prior host role. Signal checks the registered waiter's phase after publishing its condition; event phase uses DMB+SEV, native phase uses the existing futex wake. The waiter publishes native phase and issues a full StoreLoad fence before rechecking the acquire-only atomic_t condition and entering FUTEX_WAIT with its expected value.

Named helpers receive lower-tier affinity and a uclamp max hint of 256; guest CPU and RSX promotion restore 1024. Platform-owned realtime audio callback threads are not reconfigured from within their callback. uclamp failure is non-fatal and logged once. Unsupported/restricted topology retains generic affinity. Six concurrent SPU hosts lease distinct lower-tier cores; excess hosts share the least occupied core.


## Source coverage at the phase-one checkpoint

The common path is the existing registered `atomic_wait_engine::wait`, with Cell event/native phases underneath it. It is not a replacement for every polling loop in the emulator. Untimed PPU `cpu_wait` (`PPUThread.cpp:3157–3176`), untimed lv2 sync `ppu.state.wait` sites, SPU channel pop/push (`SPUThread.cpp:8978–9160`), MFC-full waits (`:5562–5588`), and SPU state waits reach it. Ordinary wakeup still rechecks unchanged predicates; forced wakeup may return without a predicate change.

`thread_ctrl::wait_for` and `wait_for_accurate` suppress Cell events for their entire dynamic scope, including nested atomic waits. `lv2_obj::wait_timeout` also suppresses its `wait_on(state, old_state, timeout)` call (`lv2/lv2.cpp:2524–2565`). This intentionally excludes timer/usleep pacing **and timed lv2 sync timeout paths**, not only functions named sleep. Untimed sync remains eligible. A direct timed logical `wait_on` outside these scopes remains eligible at 200 us or longer; shorter waits retain the native path. Therefore this checkpoint does not eliminate all PPU wait syscalls or implement the requested fiber scheduler.

The remaining SPU paths below are unchanged from the starting source. `busy_wait(300)` is a nominal count, **not 300 us**: ARM `util/asm.hpp:236–244` polls CNTVCT until `(count / 100) * arm_timer_scale` ticks have passed, using ISB pauses. A bounded individual probe does not imply that the surrounding retry sequence has a wall-clock bound.

Remaining timed fallbacks also limit coverage:

- SPURS handover `wait_for(300)` at `:6070` and compile-pressure `wait_for(200)` at `:7464` are native because of scoped suppression. The SPURS `wait_on(group->spurs_running, ...)` at `:6111` is instead eligible; its enclosing existing task-duration timeout is clamped to 10–100 ms (`:6088`).
- Pure LR reservation notifier wait `:7486` uses 200 us and is eligible. Linux general LR fallback `:7504–7533` backs off from 50 us to 800 us by default (environment cap permits 50 us–100 ms), so only intervals reaching 200 us enter the Cell event phase; its data recheck/backoff logic remains unchanged. Non-Linux fallback `:7614` and generic event/state `wait_on(..., 100)` at `:7630` use 100 us and remain native.
- The SPU decrementer timer's `wait_for(sleep_us)` at `:6812` remains native both by helper classification and suppression. It wakes for the nearest programmed underflow or an explicit rearm notification; it is not a new polling spin.

These are coverage limits and existing contention risks, not measured regressions or performance gains of the checkpoint build. No SPU polling policy was changed during this audit.

## Wait handoff ordering proof

On successful notification, `cond_handle::wakeup`/`forced_wakeup` (`util/atomic.cpp:239–269`) publish sync values 2/3 through `atomic_t<u32>::fetch_op`. `atomic.hpp:1259–1284` performs the successful update through `atomic_storage<type>::compare_exchange`. The four-byte specialization (`:729–731`) inherits the general implementation on Android/AArch64: its override is restricted to MSVC x64. The inherited implementation (`:315–317`) explicitly invokes `__atomic_compare_exchange(..., __ATOMIC_SEQ_CST, __ATOMIC_SEQ_CST)`. Thus the **successful publication is an SC RMW**; the initial relaxed observation inside fetch_op is not the publication.

The notifier then reads the phase with an SC std::atomic load. The waiter publishes native phase with an SC store and a full `atomic_thread_fence(seq_cst)` in `handoff_to_native` before re-reading sync. This full StoreLoad barrier matters because `atomic_t::load` (`atomic.hpp:326–338`) uses acquire fences around a relaxed load, not an SC load. The opposing publication/recheck order prevents both sides from missing the native transition and the sync publication. `FUTEX_WAIT` still checks the expected sync value, covering a notification between the final user-space check and entering the kernel. Normal sync=2 is reset through set_sleep before continuing an unchanged-predicate wait; forced sync=3 exits.

`DMB ISHST` in `cell_signal` orders condition publication before SEV. It is not a substitute for the handoff's full StoreLoad fence, and is not relied on as such. The host race fixtures test the implementation; device execution of the production AArch64 fixture is a separate checkpoint. Neither constitutes exhaustive weak-memory or game validation.
